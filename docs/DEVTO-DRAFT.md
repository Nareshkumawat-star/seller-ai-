## What I built

Small sellers — Etsy and eBay shops, Shopify store owners, handmade makers, local businesses — lose
hours writing product titles, descriptions, tags, and SEO metadata. The existing shortcut is paying a
proprietary AI API per listing, which small sellers often cannot justify.

**Seller AI** turns a short product fact sheet into a complete, reviewable listing:

- SEO-friendly title, plus 2–4 alternative titles
- Short and long descriptions, key feature bullets, meta description
- Keywords and tags shaped to the target marketplace (generic, Shopify, Etsy, eBay)
- Tone control (professional, friendly, luxury, minimal, persuasive)
- English, Hindi (Devanagari), or bilingual output
- Editable fields, per-field reset, copy-one-field, copy-all, and TXT/CSV/JSON export
- Saved-listing history in the browser (no accounts, no server storage)
- Optional image upload with capability-aware vision analysis

Everything is generated by an open-weight model running locally through Ollama.

## How I built it

**Stack:** Next.js 15 App Router, TypeScript (strict), React 19, Tailwind CSS v4, Zod, Ollama,
Vitest + React Testing Library, Playwright.

**Flow:** the form is validated with Zod on the client *and* in the route handler. A dedicated
server-side prompt builder injects the selected tone, language, marketplace template, and length
guidance, and places user text inside a `<product_data>` block with instructions to treat it as data,
not instructions. The model is asked for JSON (`format: "json"`), and the response is parsed
(fences/chatter tolerated), validated against a Zod schema, and corrected for language/platform drift
with a warning instead of failing.

**Failure design:** every error path is typed — offline, model missing, timeout, rate limited,
malformed output, oversized image, vision unsupported. Local inference is slow, so the UI shows a
skeleton with honest expectations, supports cancel, keeps the user's input on failure, and never
renders model output as HTML.

**Capability honesty:** `/api/health` distinguishes "the URL answered" from "the configured model is
installed" by checking `/api/tags`, and resolves vision support from `/api/show` capabilities. If a
vision model is not configured, the image endpoint returns `vision_unsupported` rather than pretending
to analyse anything.

## Why open innovation matters here

- **Data locality.** With Ollama on the same machine, product text never leaves it. There is no
  per-listing vendor API in the path, and no silent cloud fallback.
- **Model choice.** Any compatible Qwen-family instruction model works; switching tags is an env var.
- **Cost control.** No per-token billing, no seat pricing. The trade-off is real though: local
  inference costs hardware, electricity, and maintenance time, and a 3B CPU model is slower than a
  hosted API.
- **Freedom to modify.** The marketplace templates, prompt rules, and output schema are ordinary files
  in the repo — a seller with a niche category can change the rules without asking anyone.

Compared with closed APIs: you give up hosted scale, big-model quality, and zero-setup operation; you
gain locality, predictable cost, and full control over the workflow. Both are legitimate choices.

## Honest limitations to include

- No marketplace publishing integration: generation is copy/export only, by design.
- No accounts or cloud sync; history is localStorage and browser-profile-local.
- Section-level regeneration is not implemented (whole-listing regenerate plus per-field reset is).
- Vision analysis requires a separately configured vision model and is deliberately conservative.
- Structured output uses Ollama's JSON mode plus server-side validation, not grammar-constrained
  decoding, so very small models can still fail to produce valid JSON (handled as a recoverable error).
- Hosted deployments cannot reach `localhost:11434` on your laptop; a hosted copy needs its own
  secured inference host, which is documented rather than hidden.
